## Pipeline PR #1: BC-to-Kinematic Integration for RL-after-SFT

### Summary
Created integration module connecting BC waypoint predictions with kinematic waypoint environment for RL refinement training.

### Changes

#### Created: `training/rl/bc_kinematic_integration.py`

**BCWaypointPredictor**: Wrapper for BC model to predict waypoints
- Loads BC checkpoint from file
- Provides predict() and predict_from_observation() methods
- Falls back to straight-line waypoints if no checkpoint

**DeltaWaypointModel**: MLP that learns delta corrections
- Input: vehicle state (19 dims)
- Output: delta waypoints (8, 2) = (num_waypoints, 2)
- Hidden dims: [256, 128, 64]

**SimplePPOAgent**: PPO agent for waypoint delta learning
- Actor-Critic architecture
- MSE loss for delta prediction
- Training loop with advantages

**BCKinematicIntegration**: Main integration class
- Connects BC model → kinematic environment
- Creates RL agent for delta learning
- Provides reset_with_bc() and step_with_rl() methods

### Testing Results
```
Smoke test: ✓
- Obs shape: (19,)
- Step: reward=-5.02

Training test (5 episodes): ✓
- Episodes run successfully
- Checkpoint saved: out/test_bc_kinematic/final_model.pt
- Training stats saved: out/test_bc_kinematic/training_stats.json
```

### Usage
```bash
# Train BC + RL delta
python -m training.rl.bc_kinematic_integration \
    --bc-checkpoint out/waypoint_bc/final.pt \
    --episodes 500 \
    --output-dir out/bc_kinematic

# BC only (no RL delta)
python -m training.rl.bc_kinematic_integration \
    --bc-checkpoint out/waypoint_bc/final.pt \
    --no-rl-delta

# Test mode
python -m training.rl.bc_kinematic_integration --test
```

### Architecture
```
BC Model (WaypointBCModel)
    ↓
BC Waypoints [8, 2]
    ↓
RL Delta Model (DeltaWaypointModel)
    ↓
Refined Waypoints = BC + Delta
    ↓
Kinematic Vehicle Control (steer, throttle)
    ↓
Environment (ADE/FDE rewards)
```

## Pipeline PR #4: Multi-Scenario Evaluation Runner

### Summary
Added comprehensive multi-scenario evaluation runner for the driving pipeline.

### Changes

#### Created: `training/eval/multi_scenario_eval.py`

**MultiScenarioRunner**: Orchestrates evaluation across scenario suites
- Loads BC and/or RL refinement checkpoints
- Runs multiple CARLA scenarios from configured suites
- Computes standardized metrics (ADE, FDE, completion, infractions)
- Outputs aggregated summary report with per-scenario breakdown

**ScenarioEvaluator**: Runs individual scenarios and collects metrics
- Supports dry-run mode for testing without CARLA
- Computes ADE/FDE metrics
- Tracks infractions (collisions, red light, stop sign, off-road)

**ModelLoader**: Loads BC and RL models for evaluation
- Loads WaypointBCModel from checkpoint
- Loads RL delta-waypoint model for refinement
- Graceful fallback to stub policy if models unavailable

**MultiScenarioEvalConfig**: Full configuration dataclass
- Checkpoint paths (bc, rl, ssl)
- Scenario suite selection (smoke, quick, full, adverse, night)
- Multiple runs per scenario for statistical significance
- CARLA host/port configuration

**MultiScenarioSummary**: Aggregated results
- Overall success rate, mean ADE/FDE, completion rate
- Infraction rates across all scenarios
- Per-scenario breakdown in results list

### Usage
```bash
# Run smoke suite with BC only
python -m training.eval.multi_scenario_eval \
    --bc-checkpoint out/waypoint_bc/final.pt \
    --suite smoke

# Run full suite with BC + RL refinement
python -m training.eval.multi_scenario_eval \
    --bc-checkpoint out/waypoint_bc/final.pt \
    --rl-checkpoint out/ppo_delta/final.pt \
    --suite full \
    --output-dir out/multi_scenario_eval

# Dry-run (no CARLA)
python -m training.eval.multi_scenario_eval --dry-run
```
