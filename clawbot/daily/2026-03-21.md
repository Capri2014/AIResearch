## Pipeline PR #5 (2026-03-21): GRPO Waypoint Refinement After SFT

### Summary
Added GRPO (Group Relative Policy Optimization) based waypoint refinement as an alternative to PPO for RL-after-SFT training.

### Changes

#### New File: `training/rl/grpo_waypoint_refinement.py`
- **GRPOWaypointConfig**: Configuration dataclass
  - State dim: 4 (x, y, heading, speed)
  - Num waypoints: 8
  - GRPO hyperparameters: group_size=4, beta=0.1, gamma=0.99
  
- **DeltaWaypointNetwork**: Neural network for delta-waypoint prediction
  - State encoder: Linear(4) → ReLU → Linear(64) → ReLU
  - Delta heads: 8 independent heads, each predicting (dx, dy)
  - Bounded output via tanh scaling
  
- **load_sft_waypoint_model()**: Load SFT checkpoint for initialization
  
- **train_grpo_waypoint()**: GRPO training loop with:
  - Group-relative advantage computation
  - Policy updates based on reward
  - Evaluation at intervals
  - Checkpoint saving

- **ToyWaypointEnv Integration**: Uses existing ToyWaypointEnv for:
  - Waypoint-based action space
  - Progress/reward tracking
  - Episode termination

### Architecture
**Residual Delta Learning via GRPO:**
```
final_waypoints = sft_waypoints + delta_head(z)
```

- **Option B:** Action space = waypoint deltas
- **GRPO training:** Group-relative policy optimization
- **SFT model loading:** Can initialize from trained BC checkpoint

## Pipeline PR #1 (2026-03-21): MoCo SSL + Unified Inference Pipeline

### Summary
Added MoCo-style self-supervised pretraining and unified BC+RL inference pipeline.

### Changes

#### New File: `training/pretrain/moco_waymo_ssl.py`
- **MoCoEncoder**: Momentum contrastive encoder with query/key encoders
  - Query encoder (q_enc): trained via backprop
  - Key encoder (k_enc): updated via EMA from q_enc
  - Shuffled BN for preventing shortcut learning
- **MoCoQueue**: Queue management for negative sample storage
  - FIFO queue with configurable size (default: 65536)
  - Momentum-based enqueue/dequeue
- **moco_training_loop()**: Full MoCo training loop
  - Queue-based contrastive loss (InfoNCE)
  - Momentum update (m=0.999 default)
  - Checkpoint saving with metadata

#### New File: `training/inference/pipeline_inference.py`
- **InferenceConfig**: Configuration for inference pipeline
  - BC, RL, SSL checkpoint paths
  - Device, precision, waypoint settings
  - Output directory configuration
- **InferenceResult**: Result dataclass with:
  - bc_waypoints, final_waypoints, rl_delta
  - Confidence scores (bc_confidence, rl_confidence)
  - Inference timing and mode tracking
- **PipelineInference**: Unified BC+RL inference
  - BC-only mode: direct waypoint prediction
  - BC+RL mode: waypoint + delta refinement
  - Batch inference support

#### Updated: `training/pretrain/__init__.py`
- Added MoCoEncoder, MoCoQueue, load_moco_checkpoint exports

## Pipeline PR #2 (2026-03-21): SimCLR SSL Pretraining for Waymo Data

### Summary
Implemented SimCLR (Simple Contrastive Learning of Visual Representations) as an alternative SSL approach to MoCo. Provides method diversity for ensemble representations.

### Changes

#### New File: `training/pretrain/simclr_waymo_ssl.py`
- **SimCLRConfig**: Configuration dataclass
  - Encoder types: resnet34, resnet50, efficientnet_b0, or simple CNN fallback
  - Temperature: 0.07 (default for NT-Xent)
  - Projection hidden dims based on encoder type

- **SimCLREncoder**: CNN encoder with projection head
  - ResNet34/50 backbones (with torchvision) or simple CNN fallback
  - Projection: feature_dim → 256 → 128
  - Falls back gracefully if torchvision unavailable

- **SimCLRAugmentation**: SimCLR-style augmentations
  - Random resized crop, horizontal flip
  - Color jitter (brightness, contrast)
  - Works with or without torchvision

- **SimCLRPairTransform**: Creates two augmented views

- **simclr_loss**: NT-Xent contrastive loss
  - Symmetric loss formulation
  - Normalized temperature-scaled cross entropy

- **simclr_training_loop**: Full training pipeline
  - AdamW optimizer with weight decay
  - Linear warmup + cosine LR schedule
  - Checkpointing at configurable intervals
  - TensorBoard logging (optional)

#### Updated: `training/pretrain/__init__.py`
- Added SimCLRModel, SimCLRConfig, simclr_loss exports
- Added usage documentation for SimCLR

| SimCLR | Batch | Large (64+) | Low |
| Temporal | Temporal pairs | Medium | Medium |

## Pipeline PR #4 (2026-03-21): CARLA ScenarioRunner Multi-Scenario Framework

### Summary
Added a comprehensive scenario factory and multi-scenario runner for closed-loop CARLA evaluation of driving policies.

### Changes

#### New Module: `sim/driving/carla_srunner/scenario_factory.py`
- **ScenarioType**: Enum for scenario types
  - CUT_IN, FOLLOW, LANE_CHANGE, MERGE, INTERSECTION, ROUNDABOUT, PEDESTRIAN, EMERGENCY_BRAKE, PARKING, U_TURN

- **ScenarioDifficulty**: Difficulty levels (EASY, MEDIUM, HARD)

- **ScenarioConfig**: Configuration dataclass
  - Town, weather, spawn points
  - Actor behavior parameters (speed, distance, lane offset)
  - Success criteria (acceleration limits, collision tolerances)

- **ScenarioResult**: Result dataclass
  - Timing metrics (duration, start/end time)
  - Performance metrics (distance, speed, acceleration)
  - Safety metrics (collisions, violations, off-road)
  - Waypoint metrics (ADE, FDE, MSE)
  - Goal achievement tracking

- **ScenarioFactory**: Factory for creating scenarios
  - `create_cut_in_scenario()`, `create_follow_scenario()`, etc.
  - Weather presets (ClearNoon, CloudyNoon, RainyNoon, FoggyNoon)
  - Spawn point management for different towns

- **MultiScenarioConfig**: Configuration for running multiple scenarios
  - Scenario list, output directory, retry logic
  - Parallel execution support
  - CARLA connection settings

- **MultiScenarioRunner**: Execute multiple scenarios
  - Result aggregation and statistics
  - Save trajectories and metrics to JSON

- **create_standard_scenario_suite()**: Helper to create evaluation suite

- Tests for all major components

### Usage
```python
from sim.driving.carla_srunner.scenario_factory import (
    ScenarioFactory,
    ScenarioType,
    ScenarioDifficulty,
    MultiScenarioRunner,
    MultiScenarioConfig,
)

# Create scenarios
factory = ScenarioFactory()
scenarios = [
    factory.create_cut_in_scenario(town="Town01", difficulty=ScenarioDifficulty.EASY),
    factory.create_follow_scenario(town="Town01", following_distance=15.0),
    factory.create_lane_change_scenario(town="Town01", target_lane=1),
]

# Run multi-scenario evaluation
config = MultiScenarioConfig(
    scenarios=scenarios,
    output_dir="out/scenario_results",
)
runner = MultiScenarioRunner(config)
result = runner.run_all()
runner.save_results(result)

print(f"Success rate: {result.success_rate*100:.1f}%")
```
